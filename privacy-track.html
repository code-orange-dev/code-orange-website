Program architecture

Structured learning gets shorter. Contribution gets deeper.

Privacy Engineering Foundations · 4–6 weeks

Threat modeling, transaction graph analysis, wallet and network privacy, chain surveillance heuristics and a reusable framework: adversary → observations → heuristics → leakage → mitigation → trade-offs.

Protocol & Code Labs · 8–10 weeks

Study privacy systems through specifications, implementation, tests, historical issues, active PRs and real contribution opportunities. Candidate domains include Silent Payments, Payjoin, wallet privacy, network privacy and Lightning.

Contributor Rotations · 6–8 weeks

Explore 2–3 projects. Build them, test real changes, review work, investigate issues and produce useful evidence across multiple contribution modes.

Contributor Residency · 12–16 weeks

Choose one primary upstream project. Classroom instruction fades while participants identify useful work, engage maintainers and develop independence.

Fellowship · 3–6 months

Selective funded time for contributors demonstrating technical depth, reliability, review judgment, initiative and a credible path toward sustained project involvement.

Alumni Retention · through 12 months

Review Club, contributor calls and mentoring continue while Code Orange measures meaningful activity at 3, 6 and 12 months.

Core contributor loop

Review is a contribution.

READ → BUILD → TEST → REVIEW → CONTRIBUTE → MAINTAIN

The biweekly Code Orange Privacy Review Club uses real upstream PRs. Participants check out the branch, build it, run tests, read the surrounding code and history, discuss privacy and implementation trade-offs, and only then provide upstream feedback when they have something genuinely useful to add.

LEVEL 1

Reproduce

Build and test the change; report reliable results.

LEVEL 2

Explain

Accurately explain motivation, code paths and implementation.

LEVEL 3

Challenge

Identify edge cases, missing tests or assumptions.

LEVEL 4

Review

Provide substantive conceptual or code feedback upstream.

LEVEL 5

Own

Independently review unfamiliar work and become a recurring reviewer.

What counts

Proof-of-work is broader than authorship.

Every technical module engages participants with a real open-source codebase and produces verifiable proof of work. We do not require a PR after every session.

Code & tests

Patches, bug fixes, tests, fuzzing, benchmarks, refactors and implementation work.

Review & validation

Substantive reviews, PR testing, reproduction, edge-case analysis and review discussion.

Issues & research

Issue investigation, root-cause analysis, protocol research and privacy threat models.

Communication & maintenance

Documentation, maintainer discussions, triage, peer support, recurring review and mentoring.

Measuring success

Measure contributor maturity and retention.

PR counts remain useful evidence, but they are not the objective. We separate activity outputs from outcomes that demonstrate contributor growth.

Contribution readiness

Can independently build, navigate, test, review and communicate around scoped upstream work.

Meaningful activity

Authorship, reviews, testing, issues, tests, research, documentation and technical discussion.

Contributor depth

Repeated useful interactions with the same project and increasing scope of work.

Upstream usefulness

Evidence that maintainers and experienced contributors value the participant's continued involvement.

Retention

Meaningful open-source activity measured at 3, 6 and 12 months.

Progression

Fellowships, grants, regular review, maintainer responsibility, OSS work and mentoring.

North-star outcome

Participants who remain meaningfully active in at least one Bitcoin privacy-related open-source project six months after structured training ends.

Depth over repository count

Explore broadly. Contribute deeply.

Instead of optimizing for contributions across 10+ repositories, participants explore 4–6 projects, rotate through 2–3, and ultimately develop depth in one primary project. Candidate ecosystems include Bitcoin Core, rust-bitcoin, BDK, Payjoin, Silent Payments tooling, Lightning projects, network-privacy tooling and Fedimint where relevant. Actual work follows active upstream priorities.
